# Карточки блюд MOJO — редактор в Академии

Маршрут в Telegram Mini App: **Курсы → Карточки блюд · управление** (для `manager` / `local`).
Для официантов/стажёров: **Курсы → Карточки блюд** — только опубликованные позиции.

## Возможности

- Администратор загружает PDF станционок (до 20 000 000 байт) напрямую в закрытый API Академии.
- PyMuPDF извлекает встроенные фотографии, текстовые названия, ингредиенты, фрагменты описаний и номера страниц. **Без обращения к стороннему ИИ.**
- Всё импортируется **черновиками** в PostgreSQL; фото хранятся в `BYTEA`, не публикуются в GitHub или общедоступном каталоге.
- Менеджер видит замечания, меняет название, ингредиенты, описание, фотографию, архивирует устаревшую позицию и вручную подтверждает публикацию.
- После редактирования опубликованного блюда оно снова становится черновиком.
- Одинаковый PDF не дублируется при повторном импорте благодаря `source_hash + page + slot`.
- Сотрудники видят только опубликованные карточки; вход и права проверяются существующей Telegram-сессией.
- Курсы и тесты не меняются; карточки — отдельная база знаний.

## Ограничения распознавания

PDF MOJO не всегда имеет однозначное соответствие фото и рецепта. Особенно тщательно проверять страницы с двумя блюдами и фото, изменения рецептов, аллергены, неполные описания. **Импорт никогда не публикует всё автоматически.** Для PDF без текстового слоя может потребоваться ручное заполнение.

## Безопасный выпуск на Selectel

1. Дождаться зелёного CI для PR, согласовать/влить ветку в `main`.
2. В SSH на Selectel: `cd /opt/service`, затем `git status --short`. При незнакомых изменениях — остановиться.
3. Создать резервную копию: `sudo bash pilot/backup.sh`.
4. Обновить только Академию: `git pull --ff-only origin main`, затем `sudo bash pilot/update-pilot-only.sh`.
5. Чтобы разрешить PDF и загрузку фото через Caddy: `sudo bash pilot/enable-dish-upload.sh`. Скрипт делает резервную копию конфигурации, проверяет её и откатывает при ошибке. **Не запускать `deploy-pilot.sh`**, он может перезаписать прокси других приложений.
6. Открыть Telegram → Академия → Курсы → Карточки блюд · управление. Загрузить PDF и убедиться, что позиции появились черновиками.
7. Проверить минимум три разные карточки, их фотографии, ингредиенты и номера страниц. Исправить ошибки, только затем публиковать.
8. На учётной записи официанта убедиться, что черновики скрыты, опубликованная карточка видна, а после правки менеджером снова скрыта.
9. После перезапуска API проверить сохранность карточек в PostgreSQL.

### Тесты

В папке `pilot` после `pip install -r requirements.txt`:

```bash
python -m unittest test_dishes test_cases test_pilot
node --check dishes.js
```

CI запускает тесты на отдельной тестовой PostgreSQL. Это не заменяет проверку на настоящем Selectel и телефоне.

### Важное разделение

Этот PR интегрирует **редактор карточек в кабинет менеджера Академии**. Он не загружает конфиденциальный PDF в GitHub, не импортирует его в рабочую базу без явного действия менеджера, не обновляет учебные курсы автоматически и не требует Yandex AI ключа.

## Учебные курсы из карточек и текстовые главы (обновление)

После выпуска обновления в кабинете **Курсы → Управление материалами** для каждого существующего курса появились действия:

1. **Собрать главы из карточек.** Выберите только проверенные и опубликованные блюда и расположите их по порядку. Если в источнике указан диапазон страниц, кнопка предложит карточки с этих страниц (это лишь предложение, не автопубликация). Сотрудник читает фото, состав и описание как последовательность глав, нажимает «Прочитано» и переходит к тесту курса. Сами тесты, результаты и назначения остаются прежними.
2. **Редактор текстовых глав.** Для кофе, сервисных стандартов и других направлений создайте главу: заголовок, текст, источник. Меняйте порядок, добавляйте и убирайте главы без вставки огромного текста PDF. После чтения также открывается уже существующий тест.
3. **Презентация блюда с ИИ.** На утверждённых карточках появляется поле ответа «Как ты расскажешь гостю?». Ответ отправляется в Yandex AI Studio, сравнивается с утверждённой рецептурой и даёт развивающую обратную связь. Это не экзамен и не допуск, история сохраняется в отдельной таблице.

**Нельзя одновременно смешивать два режима в одном курсе:** если есть выбранные карточки, текстовый редактор попросит сначала убрать их. При изменении опубликованной карточки она временно становится черновиком, пока менеджер не проверит актуальность; курс сохранит привязку, а сотрудник не получит устаревшую главу.

### Зависимости и проверка

Это обновление включает изменения редактора PDF и учебных маршрутов. Достаточно **одного** выпуска соответствующей итоговой ветки. Порядок:

- Проверить GitHub Actions в PR; подготовить и проверить резервную копию.
- Слить итоговый PR в `main`.
- На Selectel: `cd /opt/service`, `git status --short` (должен быть пуст), `git pull --ff-only origin main`.
- `sudo bash pilot/update-pilot-only.sh` обновляет API Академии без пересоздания PostgreSQL или бота.
- `sudo bash pilot/enable-dish-upload.sh` разрешает PDF в маршруте Академии Caddy. Не используйте старый `deploy-pilot.sh`.
- Открыть Mini App менеджером, импортировать PDF, вручную проверить несколько карточек, отредактировать и опубликовать, затем привязать их к курсу. Открыть этот же курс стажёром, прочитать главы, пройти тест и убедиться, что результат пережил повторный вход.
- Для ИИ-практики нужны действующие `YANDEX_API_KEY` и `YANDEX_FOLDER_ID` **только на сервере**. Без них обучающие главы и тесты работают, а практика сообщит, что интеграция не настроена.
- Проверить, что другие приложения на сервере не затронуты. При ошибке остановиться и сохранить вывод без ключей.

**Ограничения:** это пока не генератор новых тестов по PDF. Он намеренно не создаёт и не публикует неверифицированные вопросы; использует тесты из курсов, которые менеджер проверяет самостоятельно. Не смешивать автоматический импорт карточек с подтверждением актуальных ТТК.


## Подключение Yandex AI Studio (без передачи ключа в чат)

Требуется **сервисный аккаунт** Yandex AI Studio с доступом `ai.languageModels.user`, ограниченный API-ключ для текстовой модели и ID каталога. Проверить в официальной инструкции: https://aistudio.yandex.ru/ru/docs/ai-studio/operations/generation/completions-structured

На сервере после получения ключа в панели Yandex AI Studio, **в интерактивной SSH-сессии**:

```bash
cd /opt/service
sudo bash pilot/configure-ai.sh
sudo bash pilot/update-pilot-only.sh
docker exec service-academy-api python check_ai.py
```

`configure-ai.sh` не отображает вводимый API-ключ, изменяет только `/etc/service-academy.env` и оставляет ему режим `600`. **Не вводить ключ в GitHub, ChatGPT или историю команд.** Не запускайте полное `deploy-pilot.sh`.

Если `check_ai.py` возвращает ошибку, **не обещайте сотрудникам работающую проверку ИИ**. Проверьте права сервисного аккаунта, ID каталога, активную модель, сетевое соединение и квоты в Yandex AI Studio. Текстовый курс и детерминированные тесты могут работать без ИИ.

## Контроль перед пилотом

- Пройти из настоящего Telegram под тестовым официантом: каталог → опубликованный курс → все главы → тест → результат → повторный вход. Проверить реальные записи в PostgreSQL.
- В тестовой роли менеджера убедиться, что подсказки и критерии кейса не доступны стажёру.
- Перед публикацией каждого курса исправить предупреждения о повреждённых и шаблонных вопросах; они выводятся в кабинете менеджера.
- Проверить повтор запроса ИИ при нестабильной сети: текст остаётся на экране, запрос не должен дублироваться.
- Проверить приватность материалов и снимков и отсутствие открытых портов PostgreSQL.

## Перезапуск Telegram-бота после обновления API

После успешного `pilot/update-pilot-only.sh` запусти `sudo bash pilot/update-bot-only.sh`. Скрипт использует тот же проверенный образ Академии, проверяет `Worker ready` и возвращает прежний образ, если новый воркер не поднялся. Другие контейнеры не трогает. Без этого новые исправления задержек `/start` не попадут в работающий бот.

## Обновлённый учебный маршрут и голосовой ввод

После выпуска пользовательский путь: **утверждённые карточки → чтение всех глав → тест с открытым воспроизведением ингредиентов и множественным выбором → презентация выбранного блюда → подробный разбор Yandex AI**.

- ИИ-тренировка перемещена **из карточки блюда после теста**. Это именно порядок экранов, без нового серверного запрета на практику.
- Для структурированных курсов, собранных менеджером из опубликованных карточек, вопросы формируются из **утверждённых составов**: вместо старых «какой компонент прямо указан» используются открытое воспроизведение состава и выбор нескольких правильных ингредиентов среди правдоподобных вариантов из других утверждённых блюд. Данные не выдумываются.
- Старые курсы, для которых менеджер **ещё не утвердил карточки и не собрал главы**, продолжают использовать свой старый банк вопросов. Для полноценной замены необходимо в кабинете менеджера открыть «Курсы → Карточки блюд · управление», проверить и опубликовать позиции, затем «Управление материалами → Собрать главы из карточек».
- История прежних тестов остаётся, а новая проверка сохраняет снимок фактических вопросов для каждой попытки.
- На этапе ИИ-презентации есть текстовое поле и кнопка записи голоса. Запись распознаётся SpeechKit, результат **можно исправить перед отправкой ИИ**. Аудио после обработки не хранится; сохраняются только текст и учебная обратная связь.
- Для SpeechKit сервисному аккаунту требуется дополнительная роль `ai.speechkit-stt.user` на каталог. Подходит тот же ключ, если у него есть обе роли (языковая модель + распознавание).
- На сервере нужно установить версию Академии с FFmpeg (встроен в новый Dockerfile).

После обновления Academy API и разрешения загрузки PDF включить отдельный голосовой маршрут:

```bash
sudo bash pilot/enable-voice-upload.sh
```

**Приёмка:** сотрудник на iPhone изучает курс, проходит открытый и множественный тест, открывает практику после результата, записывает 20-секундный ответ, исправляет транскрипт и получает ответ Yandex AI с конкретными сильными сторонами, ошибками и рекомендацией. При отсутствии SpeechKit сохраняется возможность напечатать ответ.
