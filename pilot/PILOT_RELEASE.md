# MOJO Academy — приёмка пилота на 20 сотрудников

Это **проверка перед выпуском**, не замена очной методологии и не обещание, что всё работает в Telegram. Запуск только после пункта «GO».

## Минимально полезная версия

Сотрудник в Telegram: вход по одобренной заявке → каталог → короткие главы → тест → результат → сценарий ответа гостю текстом → обратная связь ИИ → повторный вход с сохранённым прогрессом.

Менеджер по сервису сразу попадает в «Обзор», менеджер точки — в «Моя команда», стажёр — в «Мой путь». Менеджер: одобрение нового сотрудника → загрузка PDF → черновики глав → предложения ИИ по тестам и открытым кейсам → проверка и публикация → назначение → результаты. Раздел «Мероприятия» — очные тренинги и запись участников, без фиктивных событий. Архивирование сохраняет прежние результаты.

**Голос необязателен для первого пилота.** При его отсутствии сотрудник пишет текст. Автоматический разбор ИИ не подтверждает допуск к работе; очный «виртуальный стол» проводит руководитель.

## 1. Контент перед подключением сотрудников

- [ ] WOW и SMILE загружены через **Программы → Создать материал → PDF**; менеджер проверил главы и предложения ИИ по тестам и кейсам, затем опубликовал. При недоступном Yandex главы остаются черновиками и доступна повторная генерация.
- [ ] Один курс из действующего меню собран из утверждённых карточек блюд с правильными фото, составами и подачей. Все спорные аллергены отдельно проверены по текущей ТТК и с кухней.
- [ ] Минимум 3 качественных опубликованных кейса без подсказок в условии; критерии доступны только менеджеру и ИИ.
- [ ] Старые опубликованные тесты-угадайки архивированы после создания новых версий. Архивирование сохраняет результаты, но скрывает старые назначения.
- [ ] Менеджер проверил варианты ответов, объяснения, правдоподобность неверных вариантов и отсутствие символов-артефактов.
- [ ] У менеджера подготовлены правила допуска и перечень очных проверок.

## 2. Технический выпуск на Selectel

Используйте только SSH и контейнеры **service-academy-***. Не запускать `pilot/deploy-pilot.sh`, не пересоздавать общий Caddy/БД и не касаться premium-ai-manager.

```bash
cd /opt/service
git status --short
```

**Если есть незнакомые изменения или `??` с именами файлов, которые теперь отслеживаются GitHub, STOP.** Не удалять и не `git reset --hard`: сначала сохранить копию и выяснить конфликт.

При чистой рабочей папке:

```bash
git pull --ff-only origin main
sudo bash pilot/update-pilot-only.sh
sudo bash pilot/update-bot-only.sh
sudo bash pilot/enable-dish-upload.sh
```

`update-pilot-only.sh` делает локальный pg_dump, проверяет тесты на PostgreSQL, применяет только аддитивные изменения схемы Академии (включая таблицы мероприятий) и меняет только Академию. Важно: `pilot/backup.sh` сохраняет копию **на том же сервере**, поэтому дополнительно нужен защищённый внешний бэкап и фактическая проверка восстановления на отдельной среде.

Если нужен голос и SpeechKit подключён, дополнительно: `sudo bash pilot/enable-voice-upload.sh`. Для пилота он необязателен.

## 3. Команда, конфигурация, диагноз

```bash
docker exec service-academy-api python pilot_readiness.py
docker exec service-academy-api python check_ai.py
docker ps --format 'table {{.Names}}\t{{.Status}}'
```

Первая команда выводит агрегаты без персональных данных; должна не иметь строк `BLOCK`. Вторая должна вывести `ai_feedback_ok: True` — проверяет настоящий синтетический запрос к Yandex. Третья — контейнеры Академии должны быть запущены.

**Проверка готовности в коде не заменяет** проверку ролей, сроков обработки данных, удалённого бэкапа и восстановления, HTTPS, firewall и реального теста на iPhone.

## 4. Утверждение сотрудников

Отправленная ссылка теперь **создаёт заявку**, а не немедленный доступ. В кабинете менеджера: **Команда → Ожидает подтверждения**; сверь Telegram ID с сотрудником через независимый канал, нажми «Подтвердить доступ». Пересланная/перехваченная ссылка сама по себе не открывает сервис. Если ссылка использована не тем человеком — не одобряй аккаунт, выдай новое приглашение правильному сотруднику.

Уже созданные и активные аккаунты не блокируются изменением. До пилота проверь список этих аккаунтов и удали/отзови лишний доступ вручную по процедуре администратора.

## 5. Ручная приёмка — менеджер + два тестовых сотрудника

- [ ] Новый сотрудник с действующим приглашением **не может войти до одобрения**; невалидное приглашение не регистрирует аккаунт. После одобрения вход и уведомление работают.
- [ ] Стажёр открывает WOW → читает главы → проходит тест без видимых правильных ответов → получает оценку. После закрытия Telegram результат сохраняется.
- [ ] Стажёр открывает меню → видит реальные утверждённые фото/составы → проходит открытый ответ и множественный выбор без угадаек.
- [ ] Стажёр открывает кейс после теста → пишет ответ → получает фактический разбор Yandex (сильные стороны, ошибки, следующий шаг). При сбое текст ответа не теряется.
- [ ] Менеджер создаёт PDF-черновик, редактирует его, видит статус и публикует. Стажёр не видит черновиков и критериев кейса.
- [ ] Менеджер видит результаты обоих сотрудников. Другой стажёр не может увидеть чужие ответы или профиль.
- [ ] Менеджер начинает с «Обзор» / «Моя команда», а не с учебного прогресса 0/0. Стажёр начинает с «Мой путь».
- [ ] Менеджер создаёт тестовое мероприятие, публикует его, сотрудник записывается и отменяет запись; руководитель видит участника. Другая точка не получает доступ.
- [ ] PDF → генерация ИИ создаёт только *черновики* проверяемых вопросов и открытых кейсов; менеджер проверяет источники, правильные варианты и критические факты. При неудачной генерации главы PDF не теряются.
- [ ] Сообщение `/start` и назначение обучения приходят без необъяснимых длительных задержек; нет дублирующих уведомлений.
- [ ] У iPhone нет горизонтальной прокрутки, перекрытого нижнего меню, неверной кнопки и случайной демонстрационной статистики.
- [ ] Есть согласованный порядок работы с персональными данными, ограничения хранения ответов и процедура отзыва доступа.

## 6. GO / NO-GO

**GO на тестовую группу 2–5 сотрудников**, если пройдены автоматические и ручные проверки, есть внешний бэкап и подтверждена работа ИИ. После успешной мини-группы и исправления найденных ошибок можно расширить до ~20.

**NO-GO**, если остаются опубликованные угадайки, нет проверенного контента WOW/SMILE/меню, нет подтверждённого разграничения прав, нет резервной копии с проверенным восстановлением или ИИ не отдаёт ответы. При недоступном ИИ можно использовать отдельно обозначенную ограниченную программу «чтение + тесты» без обещаний работающих AI-кейсов.

Не публиковать в публичном GitHub реальные ТТК, PDF, персональные данные, ключи и дампы PostgreSQL.

## 7. Ограничения авторазметки курса

Yandex AI получает сокращённые выдержки из **1–16 глав**, максимум по 1250 символов текста на главу. Это предварительная методическая помощь, а не полный независимый аудит рецептур или стандартов. Для длинных документов менеджер делит материал на небольшие курсы, проверяет все главы по оригиналу, редактирует вопросы и кейсы и отдельно публикует каждую версию. Генерация не переносит фото и не изменяет разрешения сотрудников. Токены Yandex не отправлять в чат или GitHub.
